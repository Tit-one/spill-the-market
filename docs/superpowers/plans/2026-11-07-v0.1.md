# Spill the Market v0.1 Implementation Plan

**Goal:** Deliver the user-approved autonomous local application with four complete modules and a concrete module-5 roadmap.
**Architecture:** Shared Pydantic contracts, native NumPy simulation, SQLite local memory/jobs/budgets, isolated background worker, bundled React frontend. Preserve existing MiroFish.
**Spec:** ../../../PLAN-A-VALIDER.md (approved in chat on 7 November 2026).
**Execution:** Parallel independent ownership of engine, research and frontend; root owns shared contracts, persistence, API, CLI, integration and release. No live inference or paid research during development.

## Global constraints
- Adult ages strictly inclusive; individual numeric population up to 100000; bounded semantic representatives.
- Separate real API costs and fictional marketing spend; provenance and assumptions visible.
- All requested channels must execute real mechanics; never cosmetic settings.
- MiroFish and its private data/configuration remain untouched; new secrets are not copied.
- Module 5 is future work, with explicit interfaces and no fake enabled controls.

## Tasks
- [x] 1. Contracts and packaging: tests first for strict audience, valid money and offline defaults.
- [x] 2. Engine: personas, product-aware editable plans, adaptive per-channel exposure, fatigue, buying, repeatable comparisons, baseline controls and financial reports. Verify distinct channels, age bounds, accounting, budget, scale and resume.
- [x] 3. Research/memory/gateway: demo/import/public URL/API modes, provenance, FTS graph, SSRF limits, bounded spend/reservations and MiroFish import. Test offline, isolation, errors, reservations and untrusted inputs.
- [x] 4. API/CLI/worker: durable local studies, progress/cancel/resume, exports, same service contracts, local origin protection and no secret leakage. Test actual end-to-end study.
- [x] 5. Interface: bilingual guided product/audience/research/media/results/settings; real controls, traces, sources, adaptive timeline, comparison and export. Build and visually verify desktop/mobile.
- [x] 6. Release preparation: examples, methodology, future visual module, CI across supported OSes, clean-wheel install, benchmarks for complete workload, independent code review and fixes. Publication gates and exact evidence: [VERIFICATION.md](../../VERIFICATION.md), [BENCHMARKS.md](../../BENCHMARKS.md).

## Review focus
- Unknown/missing source metadata must not become invented demographics or real ad prices.
- A price variation needs its own no-campaign baseline; no duplicated buyer across channels.
- Cancelling/resuming must retain committed results and outstanding provider reservations.
- Product/age/frequency/cost edits must affect execution, not only display.
- Bundled UI must work from a clean installed wheel, with no developer Node process.
